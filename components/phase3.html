DeploymentDeployment

Deployment means controlled automation. First run is manual to provision the Vercel project. Then you add environment variables, trigger deployment again, and the app goes live. Later deployments are one-click workflow runs; only update Vercel variables when new ones are added in the project. Deployment bedeutet kontrollierte Automatisierung. Der erste Lauf ist manuell, damit das Vercel-Projekt angelegt wird. Danach Variablen in Vercel eintragen, Workflow erneut starten, und die App geht live. Spätere Deployments sind One-Click-Workflow-Läufe; Vercel-Variablen nur bei neuen Projektvariablen ergänzen.

Deployment FlowDeployment-Ablauf

⚙️GitHub Workflow → Vercel → DomainGitHub-Workflow → Vercel → Domain

Use deploy.yml manually for the first deployment. It can provision the project when VERCEL_PROJECT_ID is missing. Then add all env variables in Vercel and run deployment again. After that, deployment is repeatable and stable.Für das erste Deployment deploy.yml manuell starten. Der Workflow kann ein Projekt provisionieren, wenn VERCEL_PROJECT_ID fehlt. Danach alle Env-Variablen in Vercel eintragen und Deployment erneut starten. Ab dann ist der Ablauf wiederholbar und stabil.

1

Run deploy workflow first time (manual)Deploy-Workflow zuerst manuell starten

Open GitHub Actions and run Deploy to Vercel. First run creates or links the Vercel project.In GitHub Actions Deploy to Vercel manuell ausführen. Der erste Lauf erstellt oder verknüpft das Vercel-Projekt.

2

Add all env variables in VercelAlle Env-Variablen in Vercel eintragen

Copy variables from .env.local into Vercel Project Settings. If new variables appear later, add them before deploying.Variablen aus .env.local in Vercel Project Settings übernehmen. Wenn später neue Variablen hinzukommen, vor dem Deployment ergänzen.

3

Trigger deploy second timeDeployment zweites Mal auslösen

Run the workflow again after env setup. This is the run that typically brings the full app live correctly.Workflow nach Env-Setup erneut starten. Dieser Lauf bringt die App in der Regel korrekt live.

4

Connect Strato domain + Supabase-backed appStrato-Domain + Supabase-App verbinden

Set DNS records from Vercel in Strato, verify SSL, and test one full write/read flow to Supabase on production URL.DNS-Einträge aus Vercel in Strato setzen, SSL prüfen und einen kompletten Schreib-/Lese-Flow zu Supabase auf der Produktions-URL testen.
