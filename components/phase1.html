GitHub Copilot is an AI that lives inside VS Code and writes code alongside you. But unlike a simple autocomplete, Copilot in this project is fine-tuned to know exactly our tech stack, our rules, and our coding conventions — through a set of configuration files that ship inside template_repo.GitHub Copilot ist eine KI, die in VS Code lebt und Code neben dir schreibt. Aber anders als ein einfaches Autocomplete kennt Copilot in diesem Projekt unseren Tech-Stack, unsere Regeln und Konventionen — durch Konfigurationsdateien in template_repo.

ELI5 Analogy

Imagine having a genius friend who has read every programming book ever written, knows your project inside-out, and sits next to you while you code. When you start typing, they finish the sentence — correctly, every time. That is GitHub Copilot. The configuration files are like giving that friend a briefing document about your specific project before they start.Stell dir vor, du hast einen genialen Freund, der jedes Programmierbuch gelesen hat, dein Projekt in- und auswendig kennt und neben dir sitzt. Wenn du anfängst zu tippen, vervollständigt er den Satz — jedes Mal korrekt. Das ist GitHub Copilot.

The Database — Supabase & MCPDie Datenbank — Supabase & MCP

🗄️Where Your App Stores Its MemoryWo die App Daten speichert

Every app needs to remember things — user accounts, product listings, messages. Supabase is the cloud database that stores all of this. It is like a giant, secure filing cabinet in the cloud that your app reads from and writes to 24/7.Jede App muss Dinge speichern — Nutzerkonten, Produkte, Nachrichten. Supabase ist die Cloud-Datenbank, in der all das gespeichert wird. Es ist wie ein riesiger, sicherer Aktenschrank in der Cloud.

ELI5 Analogy — What is MCP?

MCP (Model Context Protocol) is like giving Copilot a direct phone line to Supabase. Instead of you manually clicking buttons in Supabase to create tables, you can simply tell Copilot: "Create a users table with name, email, and created_at columns" — and Copilot calls Supabase directly through MCP and does it for you.MCP (Model Context Protocol) ist wie ein direkter Telefonanschluss zwischen Copilot und Supabase. Statt manuell Tabellen anzulegen, sagt man Copilot: „Erstelle eine Nutzertabelle mit name, email und created_at" — und Copilot ruft Supabase direkt über MCP an.

The Safe Path — Branching & CI/CDDer sichere Weg — Branching & CI/CD

🛡️Never Break the Live AppDie Live-App niemals beschädigen

The main branch is the source of truth for production. It is always stable and always deployable. To add new features, you work on a separate copy called a "feature branch." Once your feature is finished and tested, you merge it in.Der main-Branch ist die Quelle der Wahrheit für die Produktion. Er ist immer stabil. Neue Features werden in einem separaten „Feature-Branch" entwickelt und erst nach Tests gemergt.

ELI5 Analogy

Imagine main is the published version of a book in the bookstore. A feature branch is your personal draft copy where you write new chapters and fix mistakes. Only when the new chapter is perfect do you send it to the publisher to update the bookstore version.main ist die veröffentlichte Version eines Buches. Ein Feature-Branch ist dein persönliches Exemplar, in dem du neue Kapitel schreibst. Erst wenn das neue Kapitel perfekt ist, schickst du es zum Verlag.

1

Create a Feature BranchFeature-Branch erstellen

Always name it feature/your-feature-name. This naming convention makes it immediately clear what the branch contains. Run: git checkout -b feature/my-featureImmer nach dem Muster feature/feature-name benennen. Ausführen: git checkout -b feature/mein-feature

2

Run Local Quality Checks Before Every PushLokale Qualitätsprüfungen vor jedem Push

npm run typecheck catches any TypeScript type errors (like trying to use a number where a word is expected). npm run lint catches code style problems. Both must pass before you push. This saves GitHub Actions minutes and prevents PR failures.npm run typecheck findet TypeScript-Typfehler. npm run lint findet Code-Stilprobleme. Beide müssen bestehen, bevor gepusht wird. Das spart GitHub-Actions-Minuten.

3

Push All Changes, Then Open the PRAlle Änderungen pushen, dann PR öffnen

Push everything you need before opening a Pull Request. Every new push to an open PR triggers the full CI pipeline — which consumes GitHub Actions minutes. Open the PR once, when you are done, not incrementally.Alles pushen, bevor ein Pull Request geöffnet wird. Jeder neue Push auf einen offenen PR löst die vollständige CI-Pipeline aus. Den PR nur einmal öffnen, wenn alles fertig ist.

4

The CI Pipeline Does the RestDie CI-Pipeline erledigt den Rest

When a PR is opened, the centralized Wamocon/github_workflow automatically fixes formatting issues, runs typecheck and lint again, and deploys a Vercel preview URL so you can review the changes live before merging to main.Wenn ein PR geöffnet wird, behebt der zentrale Wamocon/github_workflow automatisch Formatierungsprobleme, führt Typecheck und Lint aus und deployt eine Vercel-Vorschau-URL zum Testen.

Golden Rule

Never push directly to main. Never have more than one PR open at a time. Test locally first — then push — then open the PR.Niemals direkt auf main pushen. Niemals mehr als einen offenen PR gleichzeitig. Erst lokal testen — dann pushen — dann PR öffnen.

The Live Server — VercelDer Live-Server — Vercel

🌍Opening the Store to the WorldDas Geschäft für die Welt öffnen

Vercel is the platform that hosts the application. When code is merged to main, Vercel automatically picks it up and publishes the new version within minutes. It is like having a robot employee whose entire job is to update the website the moment you approve a change.Vercel ist die Plattform, die die Anwendung hostet. Wenn Code in main gemergt wird, veröffentlicht Vercel automatisch die neue Version. Es ist wie ein Roboter-Mitarbeiter, dessen einzige Aufgabe es ist, die Website sofort nach Genehmigung einer Änderung zu aktualisieren.

ELI5 Analogy

Deploying to Vercel is like printing and putting your book in the bookstore for the first time. Once it is there, every customer can read it. Every time you release a new edition (merge to main), Vercel automatically swaps the old copies with the new ones — no manual work needed.Auf Vercel deployen ist wie das Drucken und Einlegen eines Buches in den Buchladen. Jeder kann es lesen. Jedes neue Release tauscht Vercel automatisch gegen die neue Version aus.

1

Temporarily Make Repo PublicRepo vorübergehend öffentlich machen

Vercel needs to read the code to import the project. Go to Repository → Settings → General → Change visibility → Public. You will revert this to Internal immediately after.Vercel muss den Code lesen, um das Projekt zu importieren. Zu Repository → Settings → General → Change visibility → Public gehen. Danach sofort wieder auf Internal zurücksetzen.

2

Import & Deploy on VercelAuf Vercel importieren & deployen

Go to vercel.com → Add New Project → Import your repository → Deploy. Vercel will build the app and give it a public URL.Auf vercel.com gehen → Neues Projekt hinzufügen → Repository importieren → Deployen.

3

Copy Project ID → GitHub SecretProjekt-ID → GitHub Secret

In Vercel, go to Settings → General → Project ID. Copy it. In GitHub, go to Repository → Settings → Secrets → Actions → New secret. Name it VERCEL_PROJECT_ID. This connects GitHub Actions to your specific Vercel project.In Vercel zu Settings → General → Project ID gehen und die ID kopieren. In GitHub als Secret VERCEL_PROJECT_ID hinzufügen. Das verbindet GitHub Actions mit dem Vercel-Projekt.

4

Import All Environment VariablesAlle Umgebungsvariablen importieren

Go to Vercel → Settings → Environment Variables and add every variable from your .env.local file. If you skip this, the production build will fail because the app cannot find its database credentials.Zu Vercel → Settings → Environment Variables gehen und alle Variablen aus .env.local hinzufügen. Ohne diesen Schritt schlägt der Produktions-Build fehl.

5

Revert Repo to InternalRepo auf Internal zurücksetzen

Go back to Repository → Settings → General → Change visibility → Internal. The existing Vercel connection continues to work via GitHub Actions — the repo does not need to stay public.Zurück zu Repository → Settings → General → Change visibility → Internal. Die Vercel-Verbindung funktioniert weiterhin über GitHub Actions.

Pre-configured Secrets

VERCEL_TOKEN and VERCEL_ORG_ID are already configured at the GitHub organization level. You only need to add VERCEL_PROJECT_ID to the individual repository.VERCEL_TOKEN und VERCEL_ORG_ID sind bereits auf GitHub-Organisationsebene konfiguriert. Nur VERCEL_PROJECT_ID muss zum Repository hinzugefügt werden.

From Tuesday to Thursday, the team runs on a tight daily loop. Each feature is built, functionally tested in the browser, and only then pushed. High-quality Copilot prompts that produce excellent results are saved as "Golden Prompts" — a growing knowledge base for the team.Von Dienstag bis Donnerstag läuft das Team in einer engen täglichen Schleife. Jedes Feature wird gebaut, im Browser getestet und erst dann gepusht. Hochwertige Copilot-Prompts werden als „Golden Prompts" gespeichert — eine wachsende Wissensdatenbank.

Functional TestingFunktionstests

After each feature, open the browser and test every user flow end-to-end. Does clicking the button do what it should? Does the data save to Supabase? Test before committing — not after.Nach jedem Feature den Browser öffnen und jeden Nutzerflow testen. Funktioniert alles? Werden Daten in Supabase gespeichert? Vor dem Commit testen — nicht danach.

PR Quality GatePR-Qualitätsstufe
